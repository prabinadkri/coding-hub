A FEW THINGS TO KNOW
From idea to working code.
Start small, stay in control, and review what your agent changes.
01
Choose your project
Browse to an existing folder. Use a Git repository when possible so changes are easy to review and restore.
02
Describe a clear outcome
Explain the problem, the desired behavior, and how to check it. Analysis mode reads and explains. Turn on edits to let the agent modify files and execute commands.
03
Pick the right route
Automatic starts with Antigravity, then checks free OpenCode models, then local Qwen. Smart delegates implementation to free/local workers with at most two Antigravity planning/review calls. Token savings and equal quality are not guaranteed. Deep uses Pro on Antigravity. Local stays on your computer and works best for small tasks.
04
Review the result
Check changed files and test output. “Completed” means the agent finished its response; it does not guarantee correct code. Stop cancels further routing and preserves partial changes.
Useful details
Cloud access: Antigravity uses its own Google sign-in. Run agy in a terminal to sign in. Free models have provider quotas; the hub never purchases credits.
Local capacity: Qwen uses 16K context to fit modest hardware. This is below Ollama’s documented 64K+ OpenCode requirement. Small tasks are tested; long conversations may exceed the limit.
Private work: Local inference uses Ollama on this computer. Cloud tasks share their prompt and relevant files with the chosen provider. Big Pickle’s free-period data may be used to improve its model.
Permissions: Edit mode permits shell commands and is not an operating-system sandbox. Native terminal sessions are available with codehub open --backend local --project ~/my-project.
Local storage: Task records and logs live under ~/.local/state/coding-hub, outside your repository.
