CODING HUB

Three ways to use Coding Hub:
  codehub       Terminal menu and commands
  codehub app   Standalone Linux app with its own window and icon
  codehub web   Dashboard in your browser

Open Coding Hub from your Linux Applications menu for the standalone app.
Use ~/.local/bin/codehub if the command is not on your PATH.

The dashboard lets you choose a project, run a task, see live output, stop a task,
and revisit recent work. Analysis is the default; enable edits for implementation.

Automatic routing: Antigravity -> verified free OpenCode models -> local Qwen 3 8B.
Free cloud access has provider quotas. Local Qwen is best for focused, small tasks.

Projects contain saved chats in the sidebar. Reply in a chat to keep its context.
Use Project memory to pin requirements or create CODING_HUB.md.
Check the Usage tab or browser quota card for Antigravity limits and reset times.

Terminal chat: codehub chat --project ~/my-project
Resume chat: codehub chat --project ~/my-project --continue
Project rules: codehub init --project ~/my-project
Prepare a large repository: codehub index --project ~/my-project
Live quota: codehub quota

Terminal menu: codehub
Status: codehub status
Local interactive agent: codehub open --backend local --project ~/my-project

Read README.md for installation, privacy, limits, and usage.
Driver setup instructions: docs/gpu-setup.md
Task logs and settings: ~/.local/state/coding-hub (keep these private).

SMART ROUTE
Choose Smart in the app/browser or use codehub chat --backend smart --project ~/my-project --apply.
Antigravity plans/reviews; free/local workers implement. Maximum two manager calls per task.
Reported token usage is shown in the result. Lower usage and equal quality are not guaranteed.

USAGE & LIMITS
Open Usage & limits in the browser or Usage in the app.
CLI: codehub quota --provider free
Free-model remaining allowance is not reported. Local usage is not the provider quota.
Expected daily reset: 00:00 UTC (05:45 Nepal); provider Retry-After takes precedence.

WORKSPACE NAVIGATION
Chats: project, conversation, route, and message composer.
Task history: previous runs and their live output.
Models & hardware: cloud agents, local Qwen, GPU, and memory.
Usage & limits: provider quotas, free-model observations, and reset times.
Project memory: persistent instructions and pinned requirements.

The desktop app and browser share projects and saved conversations.

EXISTING CONVERSATIONS
Choose a project only for a new chat. Existing chats keep their project and
open directly to messages: yours on the right, the assistant on the left.
Expand Chat settings to change the route. Project memory in the header
opens instructions shared by every chat in that project.
